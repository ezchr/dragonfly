## How decisions are made

1. **Carry over.** Every decision in `decisions.txt` is kept by Bedrock state and Java name + properties, and
   compiled to the target version's ids. A Java block that lost a property keeps the closest state; a renamed one
   follows `javaRenames`; a removed one is decided again.
2. **Rules** for Bedrock states, items and biomes without a carried decision, in order:
   - `siblings`: other states of the same Bedrock name pick the Java block (and the properties, below).
   - `hand` / `hand-alias`: `handrules.go`.
   - `shape`: a name rewrite learned from Bedrock states with the same property names (torch -> wall_torch
     by torch_facing_direction), when it scores at least 0.95.
   - `same-name`: the Java block with the Bedrock name.
   - `rewrite`: name rewrites learned from the decided pairs (silver -> light_gray, double_slab -> slab,
     darkoak -> dark_oak, ...), most frequent first, which also bring the Java properties the rewrite always
     has (type=double).
   - `miss`: stone.

   Java properties are learned per property from the decided pairs: the Bedrock property (or pair of
   properties, or none) that best predicts the Java property, scored with each example left out, at the most
   specific level that scores at least 0.9: same Bedrock name and Java block, same Bedrock + Java property
   names, same Java block, all pairs. Unseen values follow an identity mapping when the evidence is one.
   waterlogged is always false (use `Waterlogged` when layer 1 holds water).

   Items: hand, the Java item of the Bedrock block with that name, same name, learned item then block name
   rewrites, else barrier. Biomes: hand (legacy biomes), same name, learned rewrites, else plains.
3. **nameDefault** (runtime fallback for states missing from the table) is the first decision per Bedrock name,
   replaced by one that is a Java default state. `NeighbourDependent` is carried over; for Java blocks the
   previous tables never produced, properties no Bedrock state varies are added.

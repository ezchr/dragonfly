Policy, in order:

1. `exact`: the Bedrock state appears in Geyser's Java->Bedrock table. With several Java candidates the Java block
   whose name equals the Bedrock name wins (else a preference table, else the lowest id block), and within
   the block the state with the fewest properties differing from the Java default state (then lowest id).
   waterlogged=true Java states are never chosen; use `Waterlogged` when layer 1 holds water.
2. `same-bedrock-name-overlap`: the Bedrock name is in Geyser's table but this exact state is not (unreachable
   Bedrock permutations). Pick the Java state whose Bedrock state shares the most property values;
   integer properties that differ score by closeness; ties go to the Java default state.
   Candidates include those of alias names: water <-> flowing_water and lava <-> flowing_lava (Geyser maps
   level 0 to water and levels 1-15 to flowing_water, Dragonfly emits still water with any depth).
3. `alias-overlap`: Bedrock-only names matched against another name's candidates (hard_* glass -> *,
   deprecated_anvil -> anvil, deprecated_purpur_block_* -> purpur_block, underwater_tnt -> tnt).
4. `java-same-name-default`: a Java block with the same name exists: its default state.
5. `manual`: hand table for Bedrock/Education-only blocks. frame/glow_frame map to air: Java item frames
   are entities, so a Java session has to spawn one per frame block.
6. `invisible-air`: technical blocks (unknown, moving_block, portal_placeholder), checked first.
7. `stone`: anything left. At runtime, states not in the generated table (custom registries) use the
   per-name default, else stone.
